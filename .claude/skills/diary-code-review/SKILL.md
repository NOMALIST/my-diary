# 한 줄 일기 코드리뷰

## 목적
- 실제로 문제를 일으키는 결함을 찾는 것이 우선 — 취향 차이·사소한 스타일 지적은 후순위
- 모든 지적은 근거(파일:줄 + 실패 시나리오) 필수, 추측성 지적 금지

## 리뷰 대상 정하기
1. 사용자가 파일·범위를 지정했으면 그 범위만
2. git 저장소면 `git diff` / `git diff --staged` 기준 변경분
3. 둘 다 아니면 `src/` 전체를 대상으로 하되, 최근 수정 파일 우선

## 절차
1. 대상 파일 전체를 읽고 호출 관계(route → lib) 파악
2. Next.js API 사용이 의심되면 `node_modules/next/dist/docs/`에서 해당 가이드 확인 — 이 프로젝트의 Next.js는 학습 데이터와 다른 버전
3. 아래 체크리스트 순서대로 검토
4. 지적 후보마다 "정말 재현되는가"를 코드로 재확인, 확인 안 되면 제외 또는 `추정`으로 표시
5. 필요 시 `npm run lint`, `npx tsc --noEmit`으로 보조 확인 (코드 수정은 하지 않음)

## 체크리스트 (프로젝트 고유)

### 정확성
- 날짜 키 계산(주 시작 요일, 월 경계, 타임존) 오류 — 로컬 날짜 vs UTC 혼동
- 일간/주간/월간 모드별 분기 누락, 빈 일기 처리
- 클라이언트 상태와 서버 저장 결과 불일치 (저장 후 재조회·낙관적 갱신)

### 보안·신뢰 경계
- API 입력은 전부 zod 스키마 검증을 거치는가 (`src/lib/schemas.ts`)
- Claude CLI 호출: 사용자 입력이 명령 인자로 들어가지 않는가, 셸 경유 실행이 없는가, 도구 비활성 유지 여부
- 프롬프트 인젝션: 일기 본문이 지시문으로 해석되지 않도록 구분되어 전달되는가
- 에러 응답에 내부 경로·스택 등 불필요한 정보 노출 여부

### 저장소 (`data/diary.json`)
- 모든 쓰기가 직렬화 큐를 경유하는가 (큐 우회 쓰기 = 동시 요청 시 유실)
- 원자적 쓰기(임시 파일 → 교체) 유지 여부
- 스키마 변경 시 이전 버전 파일과의 호환

### Next.js / React
- 서버 전용 코드(`fs`, `child_process`)가 클라이언트 번들에 섞이지 않는가
- `"use client"` 경계, 불필요한 리렌더·effect 의존성 오류
- 해당 버전에서 deprecated 된 API 사용 여부

### 운영
- CLI 타임아웃·프로세스 정리(좀비 프로세스) 처리
- 사용자에게 보이는 에러 메시지가 원인·조치를 알려주는가

### 일반 품질 (후순위)
- 중복 로직, 불필요한 복잡도, 이름 명확성
- 주석은 한국어, 식별자는 영어 규칙 준수

## 보고 형식
결론부터, 목록 위주로 간결하게. 한국어.

```
## 요약
- 전체 평가: 한 줄
- 심각도별 개수: 🔴 n / 🟠 n / 🟡 n

## 🔴 치명 (데이터 유실·보안·크래시)
- `파일:줄` — 문제 요약
  - 시나리오: 입력/상황 → 잘못된 결과
  - 수정 제안: 핵심만

## 🟠 중요 (기능 오류·잘못된 동작)
## 🟡 개선 (품질·유지보수)
## ✅ 잘된 점 (1~3개)
```

- 해당 항목 없으면 "없음"으로 표기
- 코드 수정은 하지 않음 — 제안만
